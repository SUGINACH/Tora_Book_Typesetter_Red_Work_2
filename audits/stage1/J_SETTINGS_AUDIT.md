## 2. Registry defaults vs `default_settings.json` (265 keys)

**Important structural fact:** `ui/assets/imud/default_settings.json` is the *original IMUD_TORANI project's* settings file (legacy vocabulary — `f-sh-title`, `prop-col`, `hdr-r-type`, …). It is **not** generated from the registry (despite the comment at settings-registry.js:2). The bridge is `legacy-settings-map.js`. The app **boots by importing it** (browser-entry.js:167-190), so *effective* runtime defaults = legacy-imported values wherever they differ; registry defaults surface only in bare/Node/test contexts.

### 3.3 Collisions / ambiguities found
1. **8 duplicate literal keys in DISPOSITIONS** (later silently overrides earlier; identical `to`/`transform` so currently benign, but a maintenance trap): `s-h0` (155 vs 324), `s-h1` (156 vs 325), `s-sh-title` (214 vs 326), `s-sh-sub` (216 vs 327), `s-sh-desc` (218 vs 328), `s-sh-sec` (220 vs 329), `s-sh-author` (222 vs 330), `s-sh-year` (224 vs 331).
2. **Dual-vocabulary split-brain (real bug class):** in `app-shell.js:loadTemplateJson`, keys that are already registry ids bypass the disposition table (756-759). A user template holding `page-num-position:"bottom_outer"` (legacy spelling of a shared key name) is passed through **without** `NUMPOS_MAP` → `mergeWithDefaults` flags `not-in-enum` but **keeps** the raw value (project-io.js:52-56, `kept:true`) → invalid enum can reach the engine. Same hazard for `page-num-format:"gematria"`. Through the *other* path (loadSettingSet/loadLegacyDefaults) the same keys DO hit their disposition transforms — two different outcomes for the same input depending on entry point.
3. **`page-num-format` disposition has no transform** (legacy-settings-map.js:281): legacy `gematria` is not in RED enum `['hebrew','decimal','daf-hebrew']` (settings-registry.js:46). It survives only because `folio.formatPageNumber`'s `default:` branch treats anything ≠ decimal/daf-hebrew as hebrew numerals (folio.js:55-61). Works by accident; enum vocabulary mismatch (gematria↔hebrew).
4. **Many-to-one lossy merges (documented, with issue ids):** `main/back/sub-shaar-count-numbering` + `*-show-number` (6 keys) → all merge into `count-shaar-pages` (EXT-18); `avoid-orphans`→`prevent-orphans-top` only and `avoid-widows`→`prevent-widows-top` only (bottom halves un-settable from legacy, 257-258); `aq-word-spacing`→`aq-enabled` (309); `h2-ornament-set`,`h2-title-ornament-top/bottom-style`→`h2-orn-top/bottom` (262-267); `h3-ornament-r/l`→single `h3-side-orn` (271-273).
5. **`hdr-verso-c-type` intentionally unmapped** (195-197) — documented deviation (reference renders h2 in verso center).
6. **Ambiguity guard present:** `h2-title-orn-mode` uses `onlyIfAbsent` so the direct `h2-orn-scope` key wins regardless of iteration order (265, 396-398, 417).

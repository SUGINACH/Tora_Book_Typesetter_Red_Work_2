פסקי ההשוואה — תשובה ישירה לשש השאלות

שאלהפסקהוכחה מרכזית (מדידה)
1. "אין חלון מתחת מילה ראשונה" אומת — קריטי מילות-החלון קיימות בשני הקבצים (3,016 מילים, FrankReal@18pt), אבל בישן החלון שומר שטח של 2 שורות גוף מתחת למילה (השורה הראשונה שחוזרת מתחת לחלון מרוחקת חציונית 18.3pt מתחתית המילה), ואילו בחדש הטקסט חודר מיד — מרחק 2.5pt בלבד. שורש: למנוע החדש אין כלל מצב 'window' (dropword.js) והמיפוי מתרגם window⇒drop (geometry-neutral).
2. "כותרות הצד לא ממוקמות ולא מיושרות כמו בישן" אומת — קריטי בישן ההערות מופיעות בשני צדי העמוד במקביל לטורים (514 מתוך 699 עמודים): עמודת-שמאל 53.5–83.5pt ועמודת-ימין 528–558pt (רוחב ~30pt). בחדש — אפס עמודים עם שני צדדים: 308 עמודים צד-שמאל בלבד ו־305 צד-ימין בלבד לפי recto/verso, ברוחב 40pt, מוגררות אל שולי הדף (22pt/592pt מהקצה). שורש: side-notes.js (outerX = margins.side×0.15) + אי-המרה px→pt.
3. "הרבה מקומות שהטקסט חופף" אומת — קריטי סריקת התנגשויות bbox שיטתית: ישן 11 זוגות ב-10 עמודים (שוליים) מול 668 זוגות ב-121 עמודים בחדש, ובנוסף 83 חפיפות של עיטורים על טקסט. הדפוס הדומיננטי: פסי H3 חוצי-טורים שהגוף זורם מתחתיהם (410 זוגות), וערימת H2×H3 (104), H3×סוגריים (87), מילת-חלון×H3 (20).
4. "עיטור בתוך הטקסט בתחילת וסוף פרק" אומת — קריטי 184 עיטורי "רומח" (lance) בחדש — מול אפס בגוף הטקסט בישן (רק 6 עיטורי שערים בשני הקבצים). 83 מהם חופפים טקסט בפועל; עיטורי פתיחת-הפרק ממוקמים במרכז הטור (412pt/200pt) במקום מרכז הבלוק החד-טורי (306pt), ובגובה 342.7pt — בתוך הזרימה, 50.8pt מתחת לתחתית כותרת ה-H2 האמיתית.
5. "אלמנטים וגדלים מול ההגדרות; שוויון הגדרות בין המנועים" גדלים תקינים אי-שוויון הגדרות כל הגדלים והגופנים לפי תפקיד תואמים את ההגדרות וזהים בין המנועים (טבלה מלאה להלן). אבל נמצאו 4 אי-שוויונות הגדרות/מיפוי שמסבירים את ההבדלים ההתנהגותיים: window⇒drop, drop-word-min-lines (שונה סמנטיקה), chapter-end-ornament (מפתח חדש ללא מקור), וסתירה פנימית h2-title-orn-mode=none מול h2-orn-scope=both.
6. "למה לא גילית בפעם הקודמת" הוגה — ומתוקן הדוח הקודם נכתב מול ייצוא 21-11 (882 עמודים) שבו מילות-החלון והערות-הצד נעדרו כליל; המנוע המעודכן החזיר אותן ולכן הממצא התיישן. חמש בדיקות לא היו קיימות במתודולוגיה הקודמת: סריקת התנגשויות bbox, סיווג ציורים וקטוריים, מדד עומק-העטיפה של החלון, דפוס צדדי ההערות, והצלבת מיפוי-ההגדרות מול אלמנטים. הפעם — כולן בוצעו (סעיף 6).
בסיס ההשוואה: הפלט של המנוע הישן = העימוד הרצוי. כל "הבדל" להלן מנוסח כסטיית המנוע החדש מהישן. כל המסקנות נגזרו מנתוני PDF פרוגרמטיים בלבד (קואורדינטות, גופנים, גדלים, ציורים, טקסט) — ללא VLM.

import fitz, json, os
OUT = "scripts/out/pdf2"; os.makedirs(OUT, exist_ok=True)
FILES = {"old": "pdf2/old_engine.pdf", "new": "pdf2/new_engine_2211.pdf"}

def dump(tag):
    doc = fitz.open(FILES[tag])
    with open(f"{OUT}/{tag}_spans.jsonl", "w", encoding="utf-8") as sf, \
         open(f"{OUT}/{tag}_drawings.jsonl", "w", encoding="utf-8") as df, \
         open(f"{OUT}/{tag}_images.jsonl", "w", encoding="utf-8") as if_:
        for pno in range(len(doc)):
            page = doc[pno]
            for blk in page.get_text("dict")["blocks"]:          # spans + כיוון כתיבה
                if blk.get("type") != 0: continue
                for line in blk["lines"]:
                    dv = line.get("dir", (1, 0))                  # dir=(cos,sin) — אנכי ⇒ כותרת-צד
                    for sp in line["spans"]:
                        if not sp["text"].strip(): continue
                        sf.write(json.dumps({"p": pno+1,
                            "b": [round(v,2) for v in sp["bbox"]],
                            "s": round(sp["size"],2), "f": sp["font"],
                            "t": sp["text"], "dir": [round(dv[0],3), round(dv[1],3)]},
                            ensure_ascii=False)+"\n")
            for dr in page.get_drawings():                        # ציורים וקטוריים — חלונות/עיטורים
                r = dr.get("rect")
                if r is None: continue
                items = dr.get("items", [])
                df.write(json.dumps({"p": pno+1,
                    "r": [round(v,2) for v in (r.x0,r.y0,r.x1,r.y1)],
                    "type": dr.get("type","?"), "kinds": "/".join(sorted(set(it[0] for it in items))),
                    "fill": str(dr.get("fill"))[:40], "n_items": len(items)},
                    ensure_ascii=False)+"\n")
            for im in page.get_image_info():                      # תמונות רסטר
                if_.write(json.dumps({"p": pno+1, "b": [round(v,2) for v in im["bbox"]]},
                    ensure_ascii=False)+"\n")
dump("old"); dump("new")

def cluster_curves(draws):            # אשכול ציורים סמוכים → אלמנט עיטור אחד
    by_page = defaultdict(list)
    for r in draws: by_page[r["p"]].append(r)
    for p, rs in by_page.items():
        rs = sorted(rs, key=lambda r: (r["r"][1], r["r"][0])); used = [False]*len(rs)
        for i, r in enumerate(rs):
            if used[i]: continue

1.3 שורש בקוד

שלוש נקודות במנוע החדש (קומיט הייצוא eb0dc362):

  1. src/engine/typography/dropword.js שורות 17, 7–9: MODES = ['drop','inline','bold','none'] — אין מצב 'window'. העיצוב מוגדר כ-geometry-neutral: "המצב 'drop' אינו מסיר מילים מהזרימה... והשורות נשארות זהות" — כלומר המילה מרונדרת מוגדלת בתוך שורה רגילה מבלי להזמין תיבת-חלון בזרימה. לכן אין עטיפה ואין שטח שמור.
  2. src/engine/core/legacy-settings-map.js:109: 'drop-word-mode': window ⇒ 'drop' עם הנמקה "אותו מנגנון חלון" — הנחה שגויה: 'window' של המקור הוא חלון גיאומטרי אמיתי עם עטיפת טקסט; 'drop' של RED הוא inline drop-cap ניטרלי-גיאומטריה. ההנחה הזו מאבדת את ההתנהגות.
  3. src/engine/core/legacy-settings-map.js:111: 'drop-word-min-lines' → 'first-word-threshold-lines' — הופך את משמעות ההגדרה: במקור = מספר השורות שהחלון תופס (2); ב-RED = סף מינימלי לאורך הפסקה בכדי לקשט בכלל. עומק החלון אבד לחלוטין.

1.4 הצעת תיקון

  1. להוסיף ב-typography/dropword.js מצב 'window' אמיתי: תיבת המילה (w×h=גודל-מילה × N שורות) מוסרת מהזרימה; מתכנן השורות מתכנן את N השורות הראשונות ברוחב מוקטן (עמודה פחות תיבת-החלון), והרנדרר מצייר את המילה בראש התיבה ואת שאר הטקסט עוטף סביבה.
  2. ב-legacy-settings-map.js: למפות window ⇒ window (ולא ⇒drop) ולתקן את ההנמקה; להוסיף מפתח יעד first-word-window-lines שאליו ימופה drop-word-min-lines במשמעותו המקורית.
  3. בדיקת רגרסיה מילת-מפתח: לכל מילת-חלון, לוודא ש-שתי השורות הראשונות אינן חודרות לרוחב המילה (סקריפט שלב 3 לעיל).

5.3 הצעת תיקון

  1. להעביר את ארבעת המיפויים הלא-שווים לסטטוס "ממופה-עם-סמנטיקה": window/min-lines/רוחב-עמודה כמו במקור; להוסיף ל-chapter-end-ornament מפתח מקור מפורש או לתעד כהטרוגני.
  2. להוסיף בדיקה אוטומטית "השוואת יעילות מיפוי": לכל מפתח מקור בעל השפעת גיאומטריה — dump של הערך היעיל אחרי המיפוי לצד הערך במקור, ולוודא זהות סמנטית (לא רק מיפוי מפתח).

ממצא 6 — מדוע לא נתגלו הבעיות בדוח הקודם הוגה

  1. בסיס השוואה שהתיישן: הדוח הקודם נכתב מול ייצוא 21-11 (882 עמודים) שבו מילות-החלון והערות-הצד נעדרו כליל (ToraWin=0, ToraMargin=0). המנוע המעודכן (22-11, 715 עמודים) החזיר אותן כמעט במלואן — ולכן "מילות-החלון אבדו" מתאים לגרסה הקודמת והסתיר את הבעיה האמיתית עכשיו: המילה קיימת אך החלון (השטח השמור מתחתיה) לא. חובת הדוח הייתה למדוד את תכונת-העטיפה, לא רק נוכחות גליפים.
  2. לא הייתה סריקת התנגשויות bbox: את ממצא "טקסט חופף ועולה אחד על השני" ניתן לגלות רק בבדיקת חיתוכי-תיבות שיטתית. הפעם — 668 זוגות מדודים ומסווגים לפי תפקיד.
  3. לא היה סיווג אלמנטרי של הציורים הווקטוריים: הפער 907 מול 1,816 ציורים קיים בנתונים אך לא פוענח. אשכול-קרבה מגלה 184 עיטורי רומח בגוף החדש מול 0 בישן — זו בדיקת "אלמנטים" שהמשתמש ביקש ושהייתה חסרה.
  4. לא נמדד דפוס הצבת הערות-הצד: הדוח הקודם דיווח על גודל/רוחב אך לא על ההבדפוס המבני — שתי עמודות-צד מקבילות בישן מול עמודה חיצונית אחת בחדש.
  5. לא הוצלב מיפוי ההגדרות מול אלמנטים בפועל: רק חילוץ ההגדרות והמיפוי בנפרד, בלי קישור למה שהתרנדר — למשל window⇒drop נראה "ממופה" על הנייר אך הסמנטיקה אבדה.

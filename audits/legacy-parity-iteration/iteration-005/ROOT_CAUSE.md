## F1 — כותרות ביניים חוצות-טורים חופפות גוף (919 זוגות ב-154 עמ')

### RC-F1a — עוגן הפס ויישור הצל (dp-planner.js/pushH3BandRecords)

**הפגם:** רשומות הפס הוצבו בטור 0 בגובה המילוי שלו, וה"צל" (רזרבציה) בטור
המשני הוצב בגובה המילוי **של אותו טור** — לא בעוגן הפס. הפרש הטורים שנותר
אחרי איזון פלחי-הזנב (גרנולריות שורה, 13–26px נמדדו) גרם לגוף הטור המשני
להמשיך מתחת לצל **בתוך טווח ה-y של הפס** — שמרונדר חוצה-טורים ברוחב מלא.
הוכחה (HTML p143, מודל): פס c0.9 ב-y=312.16–334.12 מול שורת גוף c1.52
ב-y=316.68 — חפיפה 17.44px במודל עצמו (לא בכותב ה-PDF).

**חוזה המקור (הוכח מהפורט legacy-imud-flow):** `curY = blockBottom()` —
max סמני שני הטורים (§2005); `layoutStack` מציב את הפס ב-`seg.y + 8`;
`openBlock` מתחת לפס. כלומר: **עוגן הפס = התחתית המשותפת (הטור הגבוה)
+ פער-הבלוק + ריפוד הפס; שני הטורים מפנים את אותו טווח-y והתוכן ממשיך
באותו y בשניהם.**

**התיקון:** `pushH3BandRecords` מחשב `base = max(planningUsedHeight)` מעל
כל הטורים; רשומת הפס הראשונה והצל הראשון נושאים `gapBeforePx = blockGap +
H3_TOP_PAD + (base − מילוי הטור)` — הצל מזמין את ההפרש עד העוגן (גיאומטריה
קבועה, `isFixedBandLine`). בדיקת המקום מנכה את פער הבלוק של הפס
(`cap − usedMax − bandGap ≥ roomNeeded`) — כמו `curY` של המקור שכולל
מרווח הפסקה עוקב.

### RC-F1b — שבירת שורות הפס ברוחב מלא במקום תיבת הכותרת (pipeline.js)

**הפגם:** H3 (mode=full-width) נמדד ברוחב מלא (674px) — פסים ארוכים נשארו
שורה אחת בעוד המקור עוטף ברוחב תיבת הכותרה. הוכחה מהייחוס: 252 פסים
חד-שורתיים (רוחב דיו מקס 330.3px) ו-83 דו-שורתיים — אפס חורגים
מ-H23_TITLE_W=331.38px. דוגמת v4: «ד. בשם הוצאה…» — שתי שורות בישן,
אחת בחדש ⇒ גובה פס שגוי והסחת עימוד.

**התיקון:** בפרופיל IMUD, כותרות רמות 2–3 נמדדות ב-H23_TITLE_W (אותו
רוחב תיבה כמו H2 — מקור יחיד imud-geometry; הפורט §2019 עוטף שם).

### RC-F1c — התחייבות הערות בנתיב הפיצול בלי שעת הכלה (dp-planner.js/findSplit-path)

**הפגם (נחשף ע"י שינוי הזרימה של RC-F1a):** כשפסקה עם הערות עוברת דרך
נתיב הפיצול (findSplit), ההערות התחייבו בעמוד הנוכחי **בלי** בדיקת
`pageFitsNoteBudget` — בניגוד ל-reserveAtMarker. נמדד ב-very_long/IMUD:
p600 (סופי 646), טור 0 ב-630px קיבל תקציב 112px ⇒ חריגת טור 34px.
בעקבות זה גם נסגר חור אחיז ב-reconcileNotesAfterPlacement שבדק את
**הטור האחרון** בלבד מול אמנת U-8 ("כל הטורים מעל המרזב") — כעת
`target.columns.every(...)`.

**התיקון:** שעת הכלה בנתיב הפיצול: אם התקציב אינו נכנס — הסמן והערתו
עוברים יחד לעמוד הבא (F-17): החיתוך נסוג לפני שורת הסמן; סמן בשורה 0 ⇒
נפילה לנתיב "אין פיצול" עם התחייבות מבוקרת דרך reserveAtMarker.

## 1. עקרון מנחה

**מודל פריטים אחד → צינור עימוד אחד → מדידה ושבירה פעם אחת → Planner אחד → PageModel יחיד → מקרינים טהורים.**

כל סוג תוכן — טקסט, מקטע גופן, סמן הערה, תמונה, עוגן, עיטור, פריט מותאם עתידי — הוא **מופע של אותו חוזה**. אין סוג תוכן שמקבל מסלול עימוד צדדי, מנוע שבירה משלו, מתכנן משלו או מקרין משלו.

## 2. חוזה הפריט (Unified Item)

כל פריט בזרם התוכן מממש את השדות הבאים. שדה רשומה חסרה רק כשאינה רלוונטית לסוג — לעולם לא "כי אין לנו את זה עכשיו".

```ts
Item {
  // ── זהות ומקור (בלתי-ניתנים לשינוי לאחר היצירה) ──
  id: string            // יציב, דטרמיניסטי, נגזר מהמקור (לא מונה ריצה)
  kind: KindId          // 'text' | 'noteMarker' | 'image' | 'anchor' | 'ornament' | 'custom:<x>' | ...
  sourceRange: { docId: string, start: number, end: number }  // עוגן מקור מדויק
  parentId: string|null // הבלוק/הפסקה שהפריט שייך לה
  order: number         // סדר קריאה בתוך ההורה

  // ── תוכן ומשאב ──
  payload: {
    text?: string              // טקסט מקור (לעולם לא מנורמל באובדן — נרמול מתועד והפיך)
    runs?: Run[]               // מקטעים בתוך הפריט (ראה §3)
    assetId?: string           // זהות נכס (תמונה/גופן/עיטור) מה-AssetResolver
    noteRef?: string           // ל-noteMarker: קישור חד-משמעי לגוף ההערה (Item אחר)
  }

  // ── סגנון ──
  styleRef: StyleRef     // הפניה לפתרון סגנון (לא עותק ערכים) — family, size, weight, color

  // ── מדדים (נכתבים פעם אחת ע"י MeasureAPI; קריאה בלבד לכל השאר) ──
  measured?: MeasuredItem  // advance/width, ascent/descent, height, bounds, breakOpportunities, inkBounds

  // ── אילוצי פריסה ──
  constraints: {
    atomic?: boolean          // אסור לחתוך (סמן, אטום, תמונה inline)
    keepWithNext?: boolean    // כותרת עם גוף אחריה
    splittable?: SplitPolicy  // מדיניות פיצול (הערה ארוכה, פסקה)
    overflow?: OverflowPolicy // shrink | move | diagnose (לעולם לא מחיקה שקטה)
    participates: 'inline' | 'block' | 'pageFurniture' | 'background'
  }

  // ── אבחון ──
  diagnostics: Diagnostic[]  // fallback גופן, גלישה, אי-מדידה — לעולם לא נבלעים

  // ── הקרנה ──
  projectionHint: { z?: number, clip?: Rect, transform?: Transform }
}
```

**כללי זהות:**
1. `id` נגזר מהמקור וקבוע לכל אורך הצינור — גם כשהפריט מתפצל חזותית (המשך הערה בעמוד הבא): כל המופעים מפנים לאותו `id` + `occurrence`.
2. אין מזהים זמניים שמשתנים בין ריצות (מונים רצים אסורים ב-hash).
3. מחיקת פריט אסורה; פריט שלא מוקם מדווח ב־diagnostics.

## 3. מקטעים (Runs) בתוך פריט

מילה/צירוף יכול להכיל כמה מקטעים בעלי סגנון/גופן שונים:

```ts
Run { text: string, styleRef: StyleRef, role?: 'paren'|'window'|'marker'|'custom' }
```

- המדידה מודדת **כל מקטע בגופן שלו** ומחברת לפי רצף אמיתי (kerning/GPOS כשנתמך).
- family identity נשמר לכל מקטע עד ההקרנה (DOM: span; PDF: fontKey לפי מקטע).
- **ערוץ הוכחת-יכולת קיים כבר היום:** סנטינלי ה־PUA (E101 סוגריים, E103/E104 סגנון מותאם — `pipeline.js:478-480,533-547`) וערוץ `fontKey` לפי-מילה (`geometry-projector.js:730-736` → `pdf-writer.js:348-376`) מוכיחים שמדידה והקרנה לפי-פריט עובדים; החוזה מכליל זאת למקטע.

## 4. התאמת המודלים הקיימים לחוזה (מיפוי מעבר — לשלב 2)

| קיים היום | בחוזה | הערות מעבר |
|---|---|---|
| `words[]` מחרוזות + סנטינלי PUA (`pipeline.js:465-507`) | `Item{kind:'text', payload.runs}` | adapter זמני בגבול הכניסה בלבד, עם בדיקות round-trip |
| placeholder `${E102}${marker}\uE000${text}` (`pipeline.js:492`) | `Item{kind:'noteMarker', payload.noteRef}` + פריט גוף הערה נפרד | הקישור הופך מבני; ניתוחי המחרוזות ב־6+ אתרים נגרעים |
| `scope` סוגריים (`bracket-scanner.js:51-154`) | `runs[].role:'paren'` | |
| תמונות ערוץ-צד (ornament/shaar/custom-page) | `Item{kind:'image', payload.assetId}` + `constraints.participates` | תמונת רקע = `background`; inline = `inline` |
| `customSpans/parenSpans` בשורה | `runs` בפריט | גרנולריות מקטע במקום offset מילה |
| טוקנים מורשת `{type:'h0..h7'|'p'}` | בלוקים קנוניים (parentId של פריטים) | דרך אותו adapter כניסה |
| `fnQueue {text,num,key}` / `page.footnotes` | פריטי הערה + `noteRef` | |

**כללי adapter (תוכנית §2.1-11):** כל adapter מסומן, בעל בדיקות round-trip, תאריך/תנאי הסרה, ומוגבל לגבול הכניסה/היציאה. אסור לו להפוך למסלוח runtime שני.

## 5. ממשקי המעבר בין השלבים (חוזי קלט/פלט)

כל שלב מקבל את הפלט הקפוא של קודמו ואינו מחשב מחדש עובדות שנקבעו:

| # | שלב | קלט | פלט | כלל סמכות |
|---|---|---|---|---|
| 1 | Parse+Normalize | raw text / DOCX | `DocumentModel`: בלוקים+פריטים+עוגנים (חוזה §2) | היחיד שרואה טקסט גולמי; נרמול מתועד והפיך |
| 2 | Resolve | DocumentModel | פריטים עם `assetId`/`styleRef` פתורים + AssetResolver/FontResolver יחידים | fallback גופן מדווח תמיד |
| 3 | Measure | פריטים פתורים | `measured` בלתי-ניתן לשינוי לכל פריט (כולל מקטעים, תמונות) | **מקור היחיד לכל רוחב/גובה/baseline**; cache לפי מפתח מלא |
| 4 | Break | פריטים מדודים + אילוצי שורה | `LineModel`: פריטים מסודרים+מדדים+סיבת חיתוך | היחיד שמחליט מקום שבירה; KP אחד לכל inline |
| 5 | Plan | LineModels + אילוצים + תבניות + תקציב הערות | `PagePlan`: מיקומים+סדר קריאה+rollback מתועד | היחיד שמחליט "איפה"; אינו מודד |
| 6 | Compose | PagePlan + פריטי עמוד/עיטורים/ריהוט | `PageModel` בלתי-ניתן לשינוי: bounds/baseline/transform/z | הפעלה אחת; validator שלמות |
| 7 | Project | PageModel | DOM / HTML / PDF | **טהורים**: אין מדידה, אין שבירה, אין החלטת מיקום |

כללי גבול מחייבים: (א) שלב אינו עוקף קודם; (ב) המרת יחידות בגבול מוגדר אחד; (ג) rounding מדיניות אחת; (ד) עובדה שחושבה פעמיים = פגם חוזה (ראה רגיסטר D1-D13).

## 6. אי-ווריאנטים (מה חייב להישמר — נבדק בכל שלב)

1. **שימור תוכן:** מולטיסט התווים/מילים של המקור = של הפלט (כולל נגזרים: גיליון, TOC, שערים) — הרחבת C1.
2. **שימור זהות:** לכל פריט בפלט יש `id`+`sourceRange`; אין פריט יתום; אין כפילוּת לא מתועדת.
3. **קישור הערות:** marker↔body מבני לכל אורך הצינור (כולל פיצול/המשך).
4. **family identity:** לכל מקטע גופן, עד ההקרנה.
5. **דטרמיניזם:** אותו קלט+הגדרות+נכסים+גרסה ⇒ אותו PageModel (hash יציב).
6. **טוהר מקרינים:** הפרש גאומטרי בין יעדי פלט רק מתועד כהגבלת יעד.
7. **אין השמטה שקטה:** פריט לא ממוקם/לא נמדד/נכס חסר ⇒ diagnostic.
8. **justify נשמר** כברירת מחדל מאושרת (החלטת משתמש; ביצוע בשלב 4 בלבד).
9. **ערכת 40 + שערי המקור פעילים אוטומטית** (החלטת משתמש; נבדק ברגרסיה).
10. **מורשת נשארת עד הוכחה מקצה לקצה** (החלטת משתמש; הסרה בשלב 9 בלבד).

## 7. מנגנון הרחבה (עתיד — מימוש בשלב 6, מוגדר כאן)

פריט מותאם חדש נרשם ב־**registry** אחד: `kind` → { schema, validation, resource-deps, measurement, constraints, placement-participation, diagnostics, DOM/PDF projection }. הוספת kind **אסור** שתדרוש: ענף pipeline, breaker שני, מתכנן שני, מקרין שני, או תנאים מפוזרים ב־parser/planner/renderer. תרגיל ההוכחה מוגדר בשלב 10 של התוכנית.

## 8. מילון נתונים (מחייב את כל הקוד החדש)

`פריט (Item)` · `מקטע (Run)` · `בלוק (Block)` · `מדד (MeasuredItem)` · `שורה (LineModel)` · `תוכנית עמוד (PagePlan)` · `מודל עמוד (PageModel)` · `מקרין (Projector)` · `עוגן (sourceRange)` · `נכס (assetId)` · `סמן הערה (noteMarker)` · `גוף הערה (note body)` · `ריהוט עמוד (pageFurniture)`. אין להשתמש באותו שם לנתונים שונים או בשמות שונים לאותו מושג (כיום: word/box/token; line/row; page/band — ליישוב בשלב 2).
